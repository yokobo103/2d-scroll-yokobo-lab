## 1. いま何があるか

`npm run dev` → F3 で開く「CONSTRAINED EDITOR」は、すでに次ができる。

| できること | 実装箇所 |
|---|---|
| 既存パーツをドラッグで移動 | `canvas.addEventListener('pointerdown')` |
| X/Y の数値入力・矢印ボタンで微調整（1/8/16px刻み） | `data-editor-field="x" / "y" / "snap"` |
| 足場のモジュール数・接続パターンの変更 | `data-editor-platform` |
| 移動床の軸・距離・周期・位相 | `data-editor-motion` |
| 結晶成長の方向・数・速度・安定時間・崩壊時間 | `data-editor-growth` |
| undo / redo | `state.history` |
| 区間ボタンでカメラを飛ばす | `data-editor-sections` |
| 下書きの自動保存（ブラウザ内） | `saveLocalStagePatch` |
| 差分JSONの書き出し・AI用指示のコピー | `makeStagePatch` |

**土台としては十分に良い。**座標系・スナップ・当たり判定の再計算・履歴は既に動いている。ゼロから作り直す理由はない。

## 2. 足りないもの — 4つだけ

### (1) 追加・削除・複製ができない

いまは**既に置いてあるパーツを動かすだけ**。新しい床も敵もアイテムも置けない。「コースを作る」には決定的に足りない。

### (2) 選択がドロップダウン

`<select>` からIDを選ぶ方式。`lower-crystal-nozzle-c` のようなIDを覚えていないと選べない。**画面のパーツを直接クリックできない。**

### (3) 保存が本物ではない

「差分JSONを書き出す」→ ダウンロード → AIに渡して反映してもらう、という経路。所長は「開かない・更新しない・忘れる」前提なので、**この一手間が入る時点で使われなくなる。**押したら `data/*.json` が本当に書き換わる必要がある。

### (4) 全体が見えない

ワールドは **33,648 × 4,200px**。ゲーム画面は約1,280px幅。つまり**26画面ぶんを鍵穴から覗いて編集している。**移動手段は横スライダー1本だけ。ここが体感上いちばんつらい。

## 3. もうひとつの構造上の問題 — コースが3つとも同じ

`src/course-layout.js` の `composeThreeCourseStage()` は、`data/crystal-lab-objects.json`（原本1本）を3回コピーして横に並べている。

```
コース1 = 原本 + (x    0, y    0) … 敵だけ tutorialEnemyProgression で差し替え
コース2 = 原本 + (x11216, y1200)
コース3 = 原本 + (x22432, y2400) … 敵だけ bossCourseEnemyProgression で差し替え
```

**床・足場・アイテム・仕掛けは3コースとも完全に同一。**違うのは敵の配置だけ。

つまり現状、エディタで床を1枚動かすと**3コース全部が同時に動く。**「コース1だけチュートリアルらしく直す」ができない。

### 対応方針: 触ったコースだけ独立させる（bake）

派生をいきなり全部切ると、せっかくの自動生成が消える。**編集したコースだけ、その時点の姿を自分のデータファイルへ焼き付ける。**

- 初期状態: コース1・3は派生のまま（`source: "tutorial-variant"` 等）
- 所長がコース1を編集して保存 → `data/course-01-objects.json` が生まれ、以後コース1は独立
- 未編集のコースは従来どおり原本から派生し続ける

エディタ側は「このコースは原本のコピーです。編集すると独立します」と一度だけ出す。

## 4. 使いやすさの背骨 — 3つ

ここが今回の核なので、先に原則を置く。

### 原則A: 保存は本物であること

押したら `data/*.json` が書き換わる。JSONは画面のどこにも出さない。保存前に自動でバックアップを取る。

### 原則B: 直してすぐ試せること

コースは11,216px（全力疾走でも26秒）。**直すたびに最初から走らされたら誰も使わない。**

「ここから試遊」= カーソル位置にプレイヤーを置いて即プレイ、Escで**同じ場所の編集画面へ戻る**。往復1秒。

> `docs/floors/1f/COURSE_NOTES.md` の教訓「経路の良し悪しを静的な数字だけで判断しない。実際に走らせるか、所長のプレイ所感を正とする」を、道具の側で満たす。

### 原則C: 止めるのは「静かに壊れるもの」だけ

見た目の良し悪しは検査しない（`AGENTS.md` の規約どおり）。止めるのは、画面上は正常に見えるのに壊れているものだけ。

- スイッチの相手（`activateTargetIds`）がいない
- 敵・アイテムが床から浮いている／床にめり込んでいる
- `killY` より下にパーツがある
- IDが重複している
- パーツがコース境界をまたいでいる

**モーダルで止めない。**画面の隅にバッジで出し、押すと該当パーツへ飛ぶ。

## 5. 画面設計

```
┌────────────────────────────────────────────────────────────┐
│ [コース1] [コース2] [コース3]      ●未保存  [保存] [試遊]    │  上部バー
├────────────┬───────────────────────────────────────────────┤
│ パレット    │                                               │
│            │                                               │
│ ▸ 床・足場  │          編集ビュー（ゲームと同じ絵）            │
│ ▸ 敵        │          ・クリックで選択                       │
│ ▸ アイテム  │          ・ドラッグで移動                       │
│ ▸ 仕掛け    │          ・ホイールでズーム                     │
│ ▸ 演出      │          ・中ドラッグでパン                     │
│            │                                               │
├────────────┼───────────────────────────────────────────────┤
│ 選択中の設定 │ ▁▂▃▅▂▁▃▅▇▃▁▂ ミニマップ（コース全体＋現在地） │
│ （既存パネル）│                                    ⚠検査 2件  │
└────────────┴───────────────────────────────────────────────┘
```

### 操作の語彙 — 一般的な作図ソフトに揃える

覚えることを増やさないのが最優先なので、独自操作を作らない。

| したいこと | 操作 |
|---|---|
| 置く | パレットから編集ビューへドラッグ&ドロップ |
| 選ぶ | クリック（Shiftクリックで複数選択） |
| 動かす | ドラッグ／矢印キー（1px）／Shift+矢印（8px） |
| 消す | Delete |
| 複製 | Ctrl+D、または Alt+ドラッグ |
| 元に戻す | Ctrl+Z / Ctrl+Shift+Z（既存の履歴を流用） |
| 移動 | ミニマップをクリックで飛ぶ／中ボタンドラッグ／ホイールでズーム |
| 保存 | Ctrl+S |
| ここから試遊 | Space（Escで編集へ戻る） |

### 置いた瞬間に正しくなる（スナップ）

浮いた敵・めり込んだ床を**そもそも作れないようにする**のが、検査より効く。

- 敵・アイテム・仕掛けをドロップ → 真下の床へ自動で接地（`floorBands` を参照）
- 床・足場をドロップ → 段の高さ（154px刻み）へ吸着
- 吸着先を破線でドロップ前にプレビュー表示
- Altを押している間だけ吸着を無効化（逃げ道は残す）

### パレットの中身

`data/prefab-registry.json` の26種を5つに束ねて出す。IDではなく**絵と日本語名**で並べる。

| グループ | 中身の例 |
|---|---|
| 床・足場 | `lab-platform-v1` / `lab-bridge-v1` / `lab-moving-platform-v1` / `lab-lift-v1` |
| 敵 | `nyabi-clean-v1` / `neji-nyabi-v1` / `nyabi-drone-v1` |
| アイテム | `data-crystal-v1` / `lab-coin-v1` / `cat-can-v1` / `fish-drink-v1` / `future-heart-v1` |
| 仕掛け | `crystal-spikes-v1` / `crystal-remote-switch-v1` / `crystal-growth-nozzle-v1` / `crystal-growth-*` / `checkpoint-v1` |
| 演出・その他 | 背景・中景・掲示など |

※ prefabには `kind` 欄がないので、**prefab → 置き先の配列（platforms / pickups / objects / actorSpawnMarkers）の対応表**を新設する必要がある。実装時の最初の作業。

## 6. 実装フェーズ

所長が早く使えるほうを先に出す。フェーズ1が終わった時点で「作れる」状態になる。

### フェーズ1 — 作れるようにする（最優先）

これだけで道具として成立する。

1. **保存の配管**: Viteのdev用ミドルウェアを追加。`POST /__editor/save` で `data/*.json` を書き込み、直前の内容を `data/.backup/` へ退避。本番ビルドには含めない
2. **クリック選択**: 編集ビューのクリック座標を当たり判定と突き合わせ、既存の `selectEntity()` へつなぐ
3. **追加・削除・複製**: パレット（この段階はテキスト一覧で可）＋ Delete / Ctrl+D。ID は `prefab名-連番` で自動採番
4. **接地スナップ**: 置いた瞬間に床へ吸着
5. **ここから試遊**: カーソル位置にスポーンして即プレイ、Escで同じ場所へ戻る

### フェーズ2 — 見通しをよくする

6. **ミニマップ**: コース全体を1本の帯で表示。床・敵・アイテムを色分けした点で描き、クリックで飛ぶ
7. **ズーム／パン**: ホイールでズーム（1/8〜1倍）、中ボタンでパン
8. **コース切替タブ**: コース1/2/3を行き来。「このコースは原本のコピーです」の一度きりの表示
9. **パレットに絵を入れる**: `asset-manifest.js` の画像をそのままサムネイルに使う

### フェーズ3 — 壊さない

10. **ライブ検査バッジ**: 原則Cの5項目。既存 `validateStage()` を拡張し、押すと該当パーツへ飛ぶ
11. **保存時に `npm run validate` を実行**: サーバ側で走らせ、結果を上部バーへ返す
12. **バックアップからの復元**: 「ひとつ前に戻す」ボタン
13. **bake**: 編集したコースを独立したデータファイルへ焼き付ける

### フェーズ4 — 速く作る

14. **区間まるごとコピー**: 範囲を選んで別の場所へ複製
15. **等間隔配置**: 選んだパーツをN個、等間隔に並べる（※ただし前回の下層の反省どおり、**等間隔コピペは退屈の元**。使いどころは背景と足場に限る）
16. **左右反転**: 区間を鏡像化
17. **区間テンプレ**: よくある形を名前付きで保存して再利用

## 7. 技術メモ（実装者向け）

### 保存エンドポイント

```js
// vite.config.js
{
  name: 'editor-save',
  apply: 'serve',                      // dev限定。本番ビルドに載せない
  configureServer(server) {
    server.middlewares.use('/__editor/save', /* 受信 → backup → 書き込み → validate */);
  }
}
```

- 書き込み先は `data/` 配下のホワイトリストのみ（パス脱出を弾く）
- 書き込み前に `data/.backup/<日時>/` へコピー
- 書き込み後に `npm run validate` を実行し、標準出力をそのまま返す

### 既存コードとの接続点

| やること | 触る場所 |
|---|---|
| 追加・削除 | `src/stage-editor.js` に `addEntity()` / `removeEntity()` を新設 |
| 当たり判定の再計算 | 既存 `buildCollisionShapes()` をそのまま呼ぶ |
| 検査の拡張 | `src/stage-resolver.js` の `validateStage()` |
| 履歴 | 既存 `state.history` に追加・削除も積む |
| 描画オーバーレイ | 既存 `drawOverlay()` を拡張（選択枠・吸着プレビュー・ミニマップ） |

### 守ること

- 既存の「AI用指示をコピー」は**残す**。所長が触って気づいたことをチャットへ持ち込む経路として機能している
- 画像倍率・接地規格は引き続き編集不可（`asset-presentation-contract` の管轄）
- 見た目の良し悪しを自動検査しない
- PC優先。スマホは試遊のみ（33,648px を指で編集させない）
