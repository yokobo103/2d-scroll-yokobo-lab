# 試作指示 — ハザードの視覚文法をあてる

> **破棄済み:** `docs/archive/work-orders/WORK_ORDER_2026-08-13.md`により置き換えられた。現在の作業・判断は新指示書を参照すること。

発行日: 2026-08-12
対象: `20260810_ニャビットの暴走実験室`
種別: **試作**。ゲーム本体には組み込まない。

## 0. これは何をする作業か

所長のレビューで、現行のハザード（噴出口・液だまり）が「めちゃめちゃ浮いている」との指摘。原因は既存の `docs/hazard-visual-contract.md` にある次の2行だと特定済み。

> 危険物は**背景テーマに合わせて色を変えず**、全階で同じ視覚言語を使う
> **丸く滑らかな器**、穏やかな噴水、水たまりに見える輪郭は**禁止**する

そして `tools/validate_hazard_visuals.py` の `MIN_DANGER_RATIO = 0.46` が、**不透明画素の46%以上をオレンジ〜赤にすること**を強制している。

この研究所の造形言語は「丸み・白/クリーム・ネイビー・ガラス・太パイプ」である。現行規格はそれを明示的に禁止し、画面の半分を赤くすることを検査で義務づけていた。**規格そのものが間違っている。**

さらに、危険色をオレンジ〜赤に固定したのも誤り。電気室で危険なのは電気、冷凍室で危険なのは冷気であり、赤ではない。

**この作業では規格を書き直さない。**規格を先に書いて生成して外す、を既に2回繰り返している。今回は**先に絵を出して、当たったものから規格を逆算する。**

## 1. 新しい原則（試作で検証したい仮説）

### 1-1. 不変量を「色」から「文法」へ移す

| 階ごとに変える | 全階で不変 |
|---|---|
| 危険の**色相**（その階のエネルギーの色） | 暗色の輪郭 / 接触面の警告帯 / 予告→発動のリズム / 外へ向かう形 |

輪郭も警告帯もリズムも、どんな色にも乗る。色を固定する必要がなかった。

### 1-2. 危険＝エネルギーが漏れている状態

各階には固有のエネルギーがある。**同じ色でも、閉じていれば装置、漏れていれば危険。**

冷凍室で、ガラス管の中で青く光っているのは装置。管が破断して外に噴いているのは危険。色ではなく**密閉／破損**で分ける。

これは `docs/FLOOR_DESIGN.md` の芯（暴走＝備品が制御を失った状態）とそのまま一致する。

| 階 | エネルギー | 危険色 | 危険＝漏れている姿 |
|---|---|---|---|
| 1F 通常ラボ | 熱・圧力 | オレンジ | 継ぎ目が開いて高温が噴く |
| 2F 電気室 | 電気 | 黄白・紫 | 碍子が割れて放電する |
| 3F 冷凍室 | 冷気 | 水色・白 | 冷却管が破断して冷気が噴く |
| 4F バイオラボ | 生体 | 緑・紫 | 培養槽が割れて胞子が漏れる |
| 5F ラボ・コア | 熱核 | 赤 | 炉壁が溶けて中身が出る |

### 1-3. 報酬との衝突を輪郭で解く

3F冷凍室では危険色が水色になり、「シアン＝報酬」と衝突する。報酬側も不変量を色から輪郭へ移す。

- **報酬の不変量** = 金色の輪郭 ＋ 浮遊 ＋ 脈動
- **危険の不変量** = 暗色の輪郭 ＋ 面に固定 ＋ 予告

金は暖色なので寒色環境でも埋もれない。`src/main.js` の `drawPickup` に `reward: true` 用の金リング（`rgba(255,222,111, ...)`）が既にあるので、土台は存在する。

## 2. 試作の設計

### 2-1. なぜ1Fと3Fを同時に出すのか

試作を先にする唯一のリスクは「**1Fだけ良く見えて他の階で崩れる**」こと。それを潰すため、**一番易しい階と一番難しい階を同時に出す。**

| | 環境色 | 危険色 | 報酬色 | 難度 |
|---|---|---|---|---|
| 1F 通常ラボ | 白・クリーム・ネイビー・シアン | オレンジ | シアン | 易（危険色が環境で唯一） |
| 3F 冷凍室 | 淡い水色・白 | **水色・白** | **シアン** | **難**（危険・報酬・環境が同じ色域） |

3Fが最悪ケース。ここで「輪郭と振る舞いだけで危険・報酬・背景が見分けられる」なら文法が証明される。2F・4F・5Fは色が独立しているので3Fより易しい。

### 2-2. 題材は「噴出口」1種に固定する

1Fと3Fで**同じ機能・同じ形状**の装置を出す。造形が違うと階の比較にならない。

- 1F: 高温噴出口（現行 `energy-vent-v1` の置き換え候補）
- 3F: 冷気噴出口（同じ装置が凍結・破断した姿）

**状態は `active`（発動中）1つだけ**でよい。idle / warning は規格確定後に作る。試作の目的は文法の判定であって、状態設計ではない。

### 2-3. バリアント

軸を2本に絞る。多いと判断できない。**基準版を1枚置き、軸ごとに片側だけ振る。**

| # | 輪郭 | 危険色の面積比 | 接地影 |
|---|---|---|---|
| **base** | 中（標準の暗色輪郭） | 約25% | あり |
| out-thin | 細く薄い | 約25% | あり |
| out-thick | 太く濃い | 約25% | あり |
| area-low | 中 | 約15% | あり |
| area-high | 中 | 約35% | あり |
| noshadow | 中 | 約25% | **なし** |

**1階あたり6枚 × 2階 = 12枚。**これ以上増やさないこと。

`noshadow` を入れる理由: 所長から「接地影が無いから浮いて見える」という別の指摘も出ている。同じ試作で同時に確かめる。

## 3. やること

### 3-1. 判定用の背景を用意する

3Fの背景素材はまだ存在しない。**生成しない。**`assets/stage01_normal_lab/runtime/parallax/near.webp` を色相回転して寒色に振った仮板を作る。

`tools/make_prototype_backdrop.py` を新設する（`tools/` の既存スクリプトと同じくPILを使う）。

- 出力: `assets/prototypes/hazard-grammar/backdrop-1f.png`（原版のまま）、`backdrop-3f.png`（寒色へ色相回転）
- 判定用の仮素材であることをファイル名とスクリプトのdocstringに明記する
- **これはゲームに組み込まない**

### 3-2. スプライトを生成する

`generate2dsprite` で12枚を生成する。プロンプトの骨子は次のとおり。**バリアント間で装置の形状を変えないこと。**

**1F 高温噴出口（base）**

> 近未来の明るい研究所にある、丸みを帯びた白とクリーム色の圧力バルブ装置。太いパイプ、ネイビーの帯、ガラスの覗き窓。装置の継ぎ目が破損して開き、そこから高温のオレンジ色の蒸気が上へ噴き出している。圧力計の針が赤く振り切れ、小さな警告灯が灯っている。**装置本体は白とクリームのまま**にする。オレンジ色は噴出物・警告灯・計器の針だけに使う。台座の接地部に暗色とオレンジの斜め警告帯。**全体を暗い輪郭線で囲む。**真横から見た正面図。背景透過。

**3F 冷気噴出口（base）**

> **1Fと同じ形状の**丸みを帯びた白とクリーム色のバルブ装置。表面に霜と氷が付着している。装置の継ぎ目が破断して開き、そこから白と淡い水色の冷気が上へ噴き出している。圧力計の針が振り切れ、小さな警告灯が灯っている。**装置本体は白とクリームのまま**にする。水色は噴出物と警告灯だけに使う。台座の接地部に暗色と水色の斜め警告帯。**全体を暗い輪郭線で囲む。**真横から見た正面図。背景透過。

各バリアントは、上のプロンプトに輪郭・危険色量の指定を足して振る。接地影はスプライトに焼き込まず、**比較シート側で描く**（実装でも共通関数で描くため）。

生成物は `assets/prototypes/hazard-grammar/` へ、生成プロンプトも併せて保存する。

### 3-3. 比較シートを作る（このタスクの肝）

`tools/build_hazard_contact_sheet.py` を新設する。

**切り抜き画像を白地に並べても判断できない。**「浮く／浮かない」は背景の上でしか分からない。過去2回の失敗はまさにそこで起きている。

シートの要件:

1. 各バリアントを、**その階の背景の上に、ゲーム内と同じ描画サイズで**配置する
2. **各バリアントの隣に必ず報酬（データ結晶＋金リング）を置く。**3Fの分離判定に必須
3. 参考として**現行の `energy-vent` を1枚同じ条件で並べる**（何が改善したか分かるように）
4. 各パターンの**実測値をラベルで表示**する — 危険色の面積比、暗色輪郭の割合。目分量と数値を突き合わせられるようにする
5. **PC相当（1536幅）と縦画面相当（390幅）の2サイズ**を出す。縦画面で潰れる案を早く落とすため
6. 接地影は `noshadow` 以外に描く。楕円で可

出力:

- `screenshots/hazard-grammar-sheet-1f.png`
- `screenshots/hazard-grammar-sheet-3f.png`
- `screenshots/hazard-grammar-sheet-mobile.png`（両階の base 系だけを縦画面幅で）

### 3-4. やってはいけないこと

- **`data/*.json` と `src/` を変更しない。**試作をゲームに組み込まない
- **`npm run validate:hazard` に試作物を通さない。**現行の検査は改訂前の規格（オレンジ〜赤46%以上）なので、今回の試作は落ちて当然である。**検査を通すために絵を赤くしないこと。**それをやると今回の作業が無意味になる
- 現行の `docs/hazard-visual-contract.md` と `tools/validate_hazard_visuals.py` を**まだ書き換えない**。所長が絵を選んでから逆算する
- 既存の `energy-vent` / `energy-spill` の素材を**上書きしない**（比較対象として残す）

## 5. この後の流れ

1. 比較シートを所長に提示する（**チャットに画像として出す**。所長にファイルを開かせない）
2. 所長が輪郭の強さ・危険色の量・接地影の有無を選ぶ
3. 選ばれた版から逆算して `docs/hazard-visual-contract.md` を全面改訂する
   - 「背景テーマに合わせて色を変えない」を削除し、**階ごとのエネルギー色**に置き換える
   - 「丸く滑らかな器を禁止」を削除し、**その階の設備と同じ造形を借りる**に置き換える
   - 危険の伝え方を「全体を赤くする」から**「破損と漏出」**へ置き換える
4. `tools/validate_hazard_visuals.py` の閾値を差し替える
   - `MIN_DANGER_RATIO = 0.46` を廃止
   - **下限・上限の両方**を持つ帯（選ばれた版の実測値から決める。目安 0.12〜0.35）
   - **危険色が一箇所に集中していること**（連結成分）を追加
   - **ベース色が階のパレットに含まれること**を追加。階パレットをデータ化する
   - 暗色アウトラインと状態差の検査は**維持**（あれは効いている）
5. 確定した規格で1Fの全ハザードを作り直し、ゲームへ組み込む

**3〜5は本指示書の範囲外。**所長の選択を待ってから別タスクとして起こす。
