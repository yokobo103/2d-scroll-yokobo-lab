# 作業指示書 — フロア別アセットカタログと世界観の育て方

発行日: 2026-08-13
対象: `20260810_ニャビットの暴走実験室`
前提資料: `docs/FLOOR_DESIGN.md`（5階層の設計正本）
**この指示書は `docs/archive/obsolete/PROTOTYPE_hazard-grammar.md` を破棄して置き換える。**

## 0. 方針転換

見た目の良し悪しを画素検査で自動判定しようとして、2回失敗した。原因は道具の当てはめ間違いである。

ラボの原則: **失敗が静かか、目に見えるかで方式を選ぶ。**検査は静かに壊れるものに使う。

- 接地基準のズレ、ビルドの素材欠落、到達不能な結晶 → 気づけない。**検査が要る**
- ハザードがダサい → **見た瞬間に分かる**。検査は要らない

`tools/validate_hazard_visuals.py` は「不透明画素の46%以上をオレンジ〜赤にする」ことを強制し、いま直そうとしている問題そのものを作った。**声の大きい失敗に、静かな失敗用の道具を当てていた。**

今回はそれをやめ、**並べて選ぶ**方式にする。所長が求めているのは次の3点である。

1. フロアごとの世界観を統一するための、**育てられる**アセットカタログ
2. **採否が簡単**にできること
3. アセットを作るための**世界観を、エージェントと所長で育て上げられる**仕組み

## 1. 仕組みの全体像

```
フロア正本（世界観）
   ↓ そのまま生成レシピになる
候補アセットを生成
   ↓ 実機背景の上に、番号をつけて並べる
所長がチャットで採否を言う（「3と5。2は色が強すぎ」）
   ↓ 採用品＋却下理由が
フロア正本に還る  ──→ 次の生成レシピが賢くなる
```

**このループが閉じていることが要件3の答えである。**採用品だけを溜めるとカタログはただの山になる。**却下と、その理由**を正本に還すから育つ。

## 2. 作る3つのもの

### 2-1. フロア正本 — `docs/floors/<floor>/CANON.md`

そのフロアの世界観の正本。**生成時はこれを丸ごと渡す。**

含めるもの:

- そのフロアの設定（`docs/FLOOR_DESIGN.md` §2 から該当階を転記）
- エネルギー・危険色・環境色
- **採用済みアセットの一覧**（サムネイルへのパスと、採用理由の1行）
- **却下されたものと理由**
- **採用の傾向 / このフロアで避けること** ← ここが育つ本体

最後の2つは、採否のたびにエージェントが追記案を出し、所長が一言で可否を返す。

### 2-2. 台帳 — `data/asset-catalog.json`

機械が読む正。UIも検査もここを見る。

```json
{
  "schemaVersion": 1,
  "entries": [
    {
      "id": "1f-hazard-vent-base",
      "floor": "1f",
      "kind": "hazard",
      "status": "candidate",
      "file": "assets/prototypes/hazard-grammar/1f/base.png",
      "recipe": "docs/recipes/hazard-vent.md",
      "intent": "破損した圧力バルブから高温が漏れている",
      "decidedOn": null,
      "reason": null
    }
  ]
}
```

`status` は `candidate` / `adopted` / `rejected` の3つ。

### 2-3. カタログシート — 画像

**所長にブラウザを開かせない。**カタログはPNGとして出力し、チャットに貼る。クリックUIは作らない。

2種類を出す。

| シート | 中身 | 用途 |
|---|---|---|
| **候補シート** | 今回の新作。**通し番号つき** | 採否を言うため |
| **正本シート** | そのフロアの `adopted` 一覧 | 「このフロアは今こう」を一目で見るため。次の生成の基準 |

## 3. 採否のやり方

所長はチャットで番号を言うだけにする。

> 「3と5。2は色が強すぎ」

エージェントがそれを台帳へ反映し、却下理由を正本の「避けること」に追記する。**所長がファイルを開く・UIを触る作業はゼロ。**

## 4. タスク

### T1. 旧仕組みを撤去する

- `tools/validate_hazard_visuals.py` を**削除**する。`package.json` の `validate:hazard` と `validate` の連鎖からも外す
- `docs/hazard-visual-contract.md` を `docs/recipes/hazard-vent.md` へ移し、**生成レシピ**に格下げする。冒頭に「これはゲートではない。生成時のプロンプト素材である」と明記する
  - 併せて内容を直す。「背景テーマに合わせて色を変えない」と「丸く滑らかな器を禁止」は**削除**する。両方とも誤りだった
  - 残す中身: **暗色輪郭 / 接触面の警告帯 / 予告→発動 / 外へ向かう形 / 危険＝エネルギーが漏れている状態**
- `docs/archive/obsolete/PROTOTYPE_hazard-grammar.md` の冒頭に「本指示書により破棄。`WORK_ORDER_2026-08-13.md` を参照」と1行入れる

**他の検査は1本も消さないこと。**接地・コース・移動・ダメージ・敵・アイテム・カメラ・音声・読み込み・表示契約・ビルドは全部「静かに壊れる」側なので残す。

### T2. 器を作る

- `data/asset-catalog.json` を新設。スキーマは §2-2
- `docs/floors/1f/CANON.md` を新設。`docs/FLOOR_DESIGN.md` §2 の 1F を転記し、「採用済み」「却下」「採用の傾向」「避けること」の空セクションを用意する
- 既存の試作12枚を `candidate` として台帳へ登録する（捨てない。造形の方向は当たっている）

### T3. シート生成器を作る

`tools/build_floor_catalog.py` を新設する。

**前回シートが使えなかった原因は背景である。**`near.webp` 1枚だけを使っていたが、これは近景レイヤーで**不透明画素が7.2%**しかない。単体では背景板にならず、下地の濃紺が透けて暗い場面になっていた。暗い背景では暗色輪郭が必ず効くので、明るい研究所で溶けないかを測れていなかった。

要件:

1. **背景は `sky` / `far` / `mid` / `near` の4枚を順に重ねた合成板**を使う。1枚だけを使わない。全フロアで同じ手順にする
2. 各アセットを**ゲーム内と同じ描画サイズ**で置く
3. **通し番号を大きく振る**（採否を番号で言うため）
4. **隣に報酬（データ結晶＋金リング）を必ず置く**。危険色と報酬色が近いフロアで分離を見るため
5. 比較用に**現行の採用品を1枚並べる**
6. 接地影はシート側で描く（実装でも共通関数で描くため）
7. **PC幅と390px幅の両方**を出す
8. 各アセットの `intent`（なぜこの案か）を1行添える

出力先: `screenshots/catalog-<floor>-<kind>-candidates.png` と `-canon.png`

**画素の測定値は出さなくてよい。**判断は目で行う。

### T4. 採否の反映と、唯一残す検査

- `tools/apply_catalog_decision.mjs` を新設。番号と判定（adopt / reject＋理由）を受けて `data/asset-catalog.json` を更新する
- `tools/validate_catalog.mjs` を新設し、`validate` の連鎖に加える
  - **検査するのは1つだけ: `data/*.json` が参照する可視アセットが、すべて `adopted` であること**
  - これは静かに壊れる。候補が本番に紛れ込んでも画面を見ただけでは分からないので、検査に値する
  - **見た目の良し悪しは一切検査しない**

### T5. 輪郭を後処理で付けられるようにする

`tools/apply_hazard_outline.py` を新設し、太さと暗さをパラメータにする。生成物は輪郭なしで出させ、後処理で乗せる。

**理由は検査のためではない。**所長が「もう少し太く」と言ったときに、**再生成せずその場で出せる**ようにするため。生成ガチャを回さずに済むので採否の回転が速くなる。実測でも、プロンプトでの輪郭指定は効いていなかった（`out-thick` が `base` より薄く出ていた）。

### T6. 1周だけ回す

**1F × ハザードだけ**で1周する。他のフロア・他の種別へ広げない。

1. 既存12枚＋追加候補を候補シートに出す
2. チャットに貼る
3. 所長の採否を待つ

仕組みが回ることを1周確認してから広げる。

## 5. 範囲外

- 2F以降のフロア正本
- ハザード以外の種別（装置・足場・小物・情報パネル・敵）
- ブラウザで動くカタログUI。**作らない。**所長はチャットだけで判断する

## 6. 完了条件

- `npm run validate` が成功する（`validate:hazard` が消え、`validate:catalog` が増えた状態）
- `npm run build` が成功する
- 候補シートがPC幅と390px幅で出力されている
- 背景が**実機と同じ明るい研究所**になっている（4枚合成が効いていること。前回の失敗の再発防止として、ここは必ず目視で確認する）
- 既存のゲーム挙動に変化がない
