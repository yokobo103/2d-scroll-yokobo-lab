## 作業A — コースデータを3本に分割

### いまの構造

`src/course-layout.js` の `composeThreeCourseStage()` が `data/crystal-lab-objects.json`（原本1本）を3回コピーし、`prefix` と `xOffset / yOffset` をかけて横に並べている。床・足場・アイテム・仕掛けは3コースとも同一で、違うのは敵だけ。

**この派生をやめ、3コースそれぞれに自分のデータを持たせる。**

### 手順

1. **移行スクリプト `tools/split_courses.mjs` を書く。**手でJSONを分けない
   - 現行の `composeThreeCourseStage()` を1度実行し、その結果をコース単位に切り出す
   - 各コースの座標は**ローカル座標へ戻す**（`xOffset / yOffset` を引く）。ワールド座標で保存しない
   - IDのプレフィックス（`c1-` / `c3-`）は剥がす。コースをまたぐID衝突は、後段の合成時にプレフィックスを付け直して防ぐ
   - 敵は `tutorialEnemyProgression` / `bossCourseEnemyProgression` を展開した結果を、そのままコース1・3のデータへ焼き込む

2. **出力先**

   | ファイル | 中身 |
   |---|---|
   | `data/course-01-objects.json` | コース1の platforms / pickups / objects / sections / floorBands / descentPoints |
   | `data/course-01-hooks.json` | コース1の playerSpawn / actorSpawnMarkers / encounterTriggers / checkpoint |
   | `data/course-02-objects.json` | 同上（現行 `crystal-lab-objects.json` の内容がほぼそのまま入る） |
   | `data/course-02-hooks.json` | 同上 |
   | `data/course-03-objects.json` | 同上 |
   | `data/course-03-hooks.json` | 同上 |

3. **`data/course-layout.json` に残すもの** — ワールド寸法・`killY`・`courseLength`・`courseVerticalOffset`・各コースのメタ（`label` / `mission` / `depthMeters` / `atmosphere` / `boss`）。
   **消すもの** — `tutorialEnemyProgression` / `bossCourseEnemyProgression`（コースデータへ焼き込み済みのため）。`source` 欄も消す

4. **`composeThreeCourseStage()` を作り直す。**原本のコピーではなく、**3本を読んでオフセットをかけて連結するだけ**にする。中の `transformEntity` / `transformActor` / `transformTrigger` / `progressiveActors` は、連結に要るものだけ残す

5. **旧 `data/crystal-lab-objects.json` / `data/crystal-lab-scene-hooks.json` は `data/archive/` へ移す。**削除しない

### 検収

- 分割の前後で**画面が変わらないこと**。`npm run validate` と `npm run build` が通り、3コースの見た目・敵配置・進行が分割前と一致する
- `npm run validate:courses`（`tools/validate_course_layout.mjs`）を、3本読み込み後の形に合わせて更新する

## 作業B — フェーズ1（作れるようにする）

`src/stage-editor.js` を育てる。作り直さない。既存の履歴・スナップ・`buildCollisionShapes()` はそのまま使う。

### B-1. 保存の配管

- `vite.config.js` に dev 限定プラグインを追加（`apply: 'serve'`。本番ビルドに載せないこと）
- `POST /__editor/save` — body は `{ file, content }`
  - 書き込み先は `data/` 配下のホワイトリストのみ。`..` を含むパスは拒否
  - 書き込み前に `data/.backup/<YYYYMMDD-HHMMSS>/` へ現行ファイルをコピー
  - 書き込み後に `npm run validate` を実行し、終了コードと標準出力を返す
- `data/.backup/` は `.gitignore` へ追加
- エディタ側は Ctrl+S と「保存」ボタン。画面にJSONを出さない。保存後は上部バーに `✓ 保存しました` か、失敗なら validate の出力を出す

### B-2. prefab → 置き先の対応表

`data/prefab-registry.json` には `kind` 欄がない。**`data/prefab-placement.json` を新設**し、26種すべてに次を持たせる。

```json
{
  "lab-platform-v1":  { "group": "床・足場", "target": "platforms", "label": "実験室の床", "snap": "shelf" },
  "nyabi-clean-v1":   { "group": "敵",      "target": "actorSpawnMarkers", "label": "ニャビクリーン", "snap": "ground" },
  "data-crystal-v1":  { "group": "アイテム", "target": "pickups", "label": "結晶データ", "snap": "ground" }
}
```

- `group` はパレットの束（床・足場／敵／アイテム／仕掛け／演出）
- `target` は追加時に入れる配列
- `snap` は `shelf`（154px刻みへ吸着）／`ground`（真下の床へ接地）／`none`
- **26種すべてに欄があることを検査する**（`npm run validate:stage` に追加）。欄の抜けは静かに壊れる

### B-3. クリック選択

- 編集ビューのクリック座標を `buildCollisionShapes()` と各エンティティの矩形に突き合わせ、既存 `selectEntity()` を呼ぶ
- 重なっている場合は同じ場所を続けてクリックすると次の候補へ回る
- Shiftクリックで複数選択。複数選択中はドラッグ・削除・複製・矢印キーが全体に効く
- 既存のドロップダウンは残す（IDが分かっているときに速いため）

### B-4. 追加・削除・複製

- **追加**: パレットの項目を編集ビューへドラッグ&ドロップ。この段階のパレットは文字一覧でよい
- **ID採番**: `<prefab名から先頭語>-<連番2桁>`（例 `lab-platform-07`）。既存IDと衝突しない番号を選ぶ
- **削除**: Delete。**そのIDを参照している仕掛けがあれば削除前に警告**（`activateTargetIds` / `nozzleId` / `attachedToTargetId` / `linkedTargetId` / `nearEntityId`）
- **複製**: Ctrl+D（右へ1モジュールずらして配置）、Alt+ドラッグ（ドラッグ先へ複製）
- 追加・削除も既存 `state.history` に積み、Ctrl+Z で戻せること

### B-5. 接地スナップ

- `snap: "ground"` — ドロップ地点の真下にある床（`floorBands` と `platforms` の両方を見る）の上面へ接地
- `snap: "shelf"` — 最下段の床から154px刻みの高さへ吸着
- ドロップ前に吸着先を破線でプレビュー
- **Altを押している間は吸着しない**（逃げ道）

### B-6. ここから試遊

- Space で、編集ビューの中央位置にプレイヤーを置いて即プレイ開始
- Esc で編集へ戻る。**カメラ位置・選択状態・ズーム率を試遊前へ復元する**
- 試遊中の取得アイテム・ダメージはエディタ状態へ持ち込まない（毎回リセット）
- 保存していない編集内容のまま試遊できること（保存を要求しない）

## 作業E — 到達ガイド（床を置いている間ずっと出す）

所長の要望。**階段配置のときだけでなく、床・足場を掴んでいる間は常に出す。**

### E-1. 先に確かめた事実

`src/player-controller.js` を読んだ結果、「ギリ届く距離」は1本の線にならない。3つの要素が足し算で効く。

| 要素 | 効き方 | 根拠 |
|---|---|---|
| スライド速度がジャンプに乗る | **+25px** | `wantsSlide` は `onGround` 必須なので空中では目標速度が430へ戻るが、`approach()` は `airAcceleration`(1250) で**減衰**するだけ。680→430に0.2秒かかり、その間だけ速い |
| コヨーテタイム 0.11秒 | **+54px** | 床を踏み外してから0.11秒はジャンプできる。走り抜けた分（47px）＋踏み外し中に12.7px落ちるぶん滞空が伸びる |
| コーナー補正 10px | **+10px** | `platformLanding()` が着地際の10pxを拾う |
| 足の内寄せ（`footInsetRatio` 0.22） | **影響なし** | 踏切側と着地側で同じだけ効くので、床の端から端の距離としては相殺される |

**結果（横）**

| 跳び方 | 渡れる隙間 |
|---|---|
| 普通に走って跳ぶ | **352px** |
| スライドジャンプ | 377px |
| コヨーテを使う | 406px |
| 両方使う | 458px |

**結果（縦）**

| | 高さ |
|---|---|
| 真上ジャンプの頂点 | **166px** |
| 実用上の段差の上限 | **154px**（既存の棚の刻みと一致） |

### E-2. 縦と横は同時に取れない

166px上がるとき、横の窓は **170〜182px しかない**（頂点付近でしか着地できないため）。逆に横352px跳ぶときは段差ゼロが上限。

| 段差 | 着地できる横の範囲 |
|---|---|
| 同じ高さ | 0〜352px |
| 77px 上がる | 46〜306px |
| 154px 上がる | 125〜227px |
| 166px 上がる | 170〜182px |

**したがってガイドを縦線と横線の2本で描いてはいけない。**「縦166・横352」と読めてしまい、両方満たす配置が存在しないのに緑に見える。

### E-3. 描くもの — 到達範囲そのもの

床・足場を掴んでいる間、**踏切になる床の端から放物線の到達範囲を描く。**

- 踏切の基準は、いま掴んでいる床にいちばん近い既存の床の端（左右どちらか、掴んでいる床がある側）
- 曲線は `y = v·(x/run) − ½g·(x/run)²` を画面座標で描いたもの
- 3本重ねる
  - **緑の実線** = 普通に走って跳ぶ（352px / 166px）
  - **黄の破線** = スライドとコヨーテを使い切った限界（458px）
  - **赤** = その外側

- 掴んでいる床の**上面の左端**が緑の内側なら緑、黄の内側なら黄、外なら赤に、床の輪郭を着色する
- 数値も併記する（例: `隙間 318px / 段差 +140px — 届く`）

### E-4. ガイドの出し方

- 床・足場を掴んでいる間だけ表示。離したら消える（画面を汚さない）
- 選択中の床がある状態で **G キー**で固定表示のオン／オフ（置いたあとに確認したいとき用）
- 敵・アイテム・仕掛けを掴んでいるときは出さない

### E-5. 守ること

- **数値をハードコードしない。**`v` `g` `maxRunSpeed` `maxSlideSpeed` `airAcceleration` `coyoteTime` `cornerCorrection` はすべて `data/player-movement.json` から読む。上の表は現在値での計算結果にすぎず、値を変えたらガイドも追随すること
- **赤でも配置は許す。**警告するだけで止めない。移動床・落下してくる経路・敵を踏んだ反動があるので、静的な計算は経路の一部しか見ていない（`docs/floors/1f/COURSE_NOTES.md` の教訓）
- 計算式は `src/reach-envelope.js` として切り出し、エディタと検査の両方から使う
- `tools/validate_reach_envelope.mjs` を追加し、上の表の数値が現在の `player-movement.json` から再現できることを検査する（移動パラメータを変えたときにガイドが黙って嘘をつくのを防ぐ）
