## 2. 設計の下敷き — 過去の実機指摘

`20260809_ピタゴラン試作` を所長が実機で触って出た指摘が、そのまま効く。**机上検証では出なかったものばかりなので、必ず守る。**

- **盤面上の小さいハンドルは指では使えない。**掴んだ指が対象を隠す。破壊的な操作は**盤面の外の操作卓**へ置く
- **ボタンは52×48px、スライダーは48px高が最低ライン**
- **細いものは「その点を含むか」ではなく「一番近いものを拾う」で判定する。**指は44px要る。20px外しても掴める距離判定にする
- **ドラッグは必ず盤面内にクランプする。**データは残っているのに描画範囲外だと「消えた」ように見える
- **「置く」で自動選択すると詰む。**パレットが消えて連続配置ができなくなる。**置いたときは選択しない**
- **iOS Safari は `user-scalable=no` を無視する。**2本目の指で拡大し、戻せなくなる。**戻せないのが一番困る**
- **マウス環境（`(pointer: fine)`）だけ盤面上の直接操作を残す**のが両取り。既存のPC操作は一切変えない

## 3. 画面設計（縦持ち 390×844 を基準）

ワールドは横長（1コース 11,216px）なので、盤面は**横帯**にして、下を全部**操作卓**にする。

```
┌───────────────────────┐ 390×844
│ [1][2][3]  ●未保存 [保存]│  上部バー 56px
├───────────────────────┤
│                       │
│      編集ビュー         │  約320px
│   （横帯・ピンチ可）      │
│                       │
├───────────────────────┤
│ ▁▂▃▅▂▁▃▅▇▃ ミニマップ  │  56px
├───────────────────────┤
│ [ 選ぶ ][ 置く ][ 試す ]  │  タブ 52px
├───────────────────────┤
│                       │
│      操作卓            │  残り約330px
│                       │
└───────────────────────┘
```

横持ちのときは編集ビューを広げ、操作卓を右側の列へ回す。**縦持ちを主にする**（横持ち前提にすると触られない）。

### タブ「選ぶ」— 選択中のパーツを直す

- 十字の微調整ボタン（各 **52×48px**）＋刻み切替（1 / 8 / 16px）
- **削除**（2段階。押す → 「消す？」→ 確定。undoで戻せる）
- **複製**
- **元に戻す / やり直す**（大きく。誤操作は前提）
- 選択中パーツの数値欄（既存の platform / motion / growth の欄をそのまま流用。入力欄の高さを48pxへ）
- **到達ガイド**のオン／オフ

### タブ「置く」— 配置モード

**ドラッグ&ドロップは使わない。**タッチでは動かないうえ、長距離ドラッグは指が対象を隠す。

1. パレットの項目をタップ → **配置モードに入る**
2. 上部に `配置中: 実験室の床 [やめる]` を出す
3. 編集ビューをタップした場所に置く。**置いても選択状態にしない**（連続で置ける）
4. 「やめる」かタブ切替で解除

- パレットは `data/prefab-placement.json` の `group` で折りたたむ。タップ的は **最低56×56px**、絵＋日本語名
- 置いた瞬間のスナップ（`applyPlacementSnap`）はPC版と同じ。Altの代わりに**「吸着しない」トグル**を操作卓へ置く

### タブ「試す」— 試遊

- **「ここから試遊」ボタン**（Spaceの代わり）
- 試遊中は仮想パッドを出し、編集UIを隠す
- 画面隅に**「編集にもどる」ボタン**（Escの代わり）。カメラ位置・選択・ズームを復元するのはPC版と同じ

## 4. ジェスチャ

| 操作 | 動き |
|---|---|
| タップ | 選択（配置モード中は配置） |
| 1本指ドラッグ（パーツの上から） | そのパーツを動かす |
| 1本指ドラッグ（何もない所から） | 盤面をパン |
| 2本指 | ピンチでズーム＋パン |

- **当たり判定は「一番近いものを拾う」。**指の位置から44px以内で最も近いパーツを選ぶ。矩形に入っているかだけで判定しない
- **ドラッグ中は、掴んだパーツを指より上へ約60pxオフセットして描く。**指で隠れると位置が合わせられない。オフセット中は元の位置に破線を残す
- **ドラッグはワールド内にクランプ**する
- 編集ビューに `touch-action: none`

## 5. iOS の拡大事故を塞ぐ

**戻せなくなるのが一番困るので、必ず両方入れる。**

- `gesturestart` / `gesturechange` を `preventDefault`
- 編集ビュー上の2本指 `touchstart` は `preventDefault` して自前のピンチへ回す
- **ただしボタン・入力欄・スライダーは除外する**（連打とフォーカスが効かなくなる）
- `visualViewport.scale` を監視し、1でないときだけ上部バーに **「表示をもどす」** ボタンを出す

## 6. スマホから開発サーバへ届かせる

1. `package.json` に **`"dev:lan": "vite --host"`** を追加（既存の `dev` は変えない）
2. 起動時に**LANのURLを大きく表示する**。所長がPC画面を見てスマホで打てる形にする
3. 保存エンドポイント `/__editor/save` は現状のまま使える。**ホワイトリストとパス検査があるので、LANに開いても書き込み先は `data/` の6ファイルに限られる**
4. `vite --host` は同一LANに公開されるため、**外出先の公衆Wi-Fiでは使わない**旨を `README.md` に1行入れる

**実機（390×844想定）で次が通ること。**PC側の操作は1つも変わっていないこと。

- キーボードなしで、エディタを開ける

## 9. 守ること

- **PCの操作を変えない。**`(pointer: fine)` のときの挙動は現状維持。スマホ用の分岐で足すだけ

## 10. 公開ビルド（GitHub Pages）での振る舞い

所長の確認（2026-08-15）「いずれGitHubにあげたときも、スマホで起動できるか」への対応。

### いまのままだと壊れる

- `src/main.js:3` の `import { createStageEditor }` は**無条件**。エディタは本番ビルドに丸ごと載る。F3も生きている（`import.meta.env.DEV` ガードが掛かっているのは `window.__qa` だけ）
- 保存は `fetch('/__editor/save')`。Pagesにこのパスは無い。**404のHTMLが返り、`response.json()` がパースに失敗する**ので、画面には `保存失敗: Unexpected token '<'...` という意味不明なメッセージが出る
- 下書きは `saveLocalStagePatch` でlocalStorageに残るため、編集内容自体は消えない
- **公開ページに誰でも開けるエディタが載る**

### 採らない案

**GitHub APIから直接コミットする案は採用しない。**ブラウザに書き込みトークンを置くことになり、公開ページである以上、**開いた人全員がリポジトリへの書き込み権を得る。**トークンを難読化しても同じ。

外出先から本物の保存をしたくなった場合は、Pagesではなく自宅PCへトンネル（Tailscale等）を掘る方向で別途検討する。PCが起動している必要があるため、いまは対象外。

### 採る案 — 「下書き＋持ち帰り」モード

1. **起動時に保存サーバの有無を判定する。**`/__editor/ping` を新設し、devプラグインが `{ ok: true }` を返す。応答が無い／JSONでない場合はサーバ無しと判定する
2. **サーバがあるとき** — 現状どおり「保存」ボタン
3. **サーバが無いとき** — ボタンが **「持ち帰る」** に変わる
   - 変更差分をクリップボードへコピー（既存の「AI用指示をコピー」の書式を流用してよい）
   - 「チャットに貼ってください」と1行出す
   - 下書きはlocalStorageに残り続ける。**貼るまで消さない**
4. **`response.json()` を素で呼ばない。**`content-type` を確認し、JSONでなければ「保存サーバがありません（公開版では持ち帰りモードを使ってください）」と出す。HTMLのパースエラーを所長に見せない

### 公開ページにエディタを出すかどうか

- 既定では**出さない**。`?editor=1` が付いているときだけ起動ボタンとF3を有効にする
- 出さない設定でも、コードは載ったままでよい（書き込み先が各自のブラウザだけなので実害がない）。バンドルサイズが問題になったら動的importへ回す
