## 所長の実機指摘（2026-08-15）

> スマホUIがものすごく使いにくい以外はひとまず動かせそう

つらかった点（所長の回答）:

1. **目当てのボタンを探すのが大変**
2. **置くのがうまくいかない**
3. **ものを置いた後に移動できない。「置く」と「選ぶ」がもっと柔軟に行き来できれば解決するのかもしれない**

「そもそもできない」と「分かりにくいだけ」は**混ざっている**。

---

## 1. 真因 — 「置く」と「選ぶ」を別タブにしたこと

前回の指示書で「**置いても選択状態にしない**」と指定した。根拠はピタゴランの実機教訓「『置く』で自動選択すると詰む。パレットが消えて連続配置ができない」。

**これは教訓の取り違えだった。**あの教訓が禁じていたのは「**パレットが消えること**」であって、「置いたものが操作対象になること」ではない。両立できるのに、排他だと決めつけて実装させた。

さらにタブで「置く」と「選ぶ」を別画面にしたため、いま置いたものを8px動かすのに:

```
置くタブで置く → 選ぶタブへ切替 → 90項目のドロップダウンか
320pxのキャンバスから対象を探す → 操作卓を数百pxスクロールして十字キー
```

**4手かかる。**これが指摘3の正体。

### 指摘2も同じ根から出ている

指で正確な位置に置くのは元々無理。だが**置いた直後にすぐ直せるなら、正確に置く必要がなくなる。**「正確に置く」問題を「置いてから直す」問題へ変換できる。タッチではこちらのほうが成立しやすい。

---

## 2. 直し方

### A. モバイルタブを廃止し、常設の操作バーを置く

`選ぶ / 置く / 試す` の3タブをやめる。**十字キー・削除・複製・undoと、パレットは常に見えている**こと。スクロールするのは詳細設定だけ。

```
┌─────────────────────────┐ 390×844
│ [1][2][3]  ●未保存 [保存][試遊]│ 上部バー
├─────────────────────────┤
│        編集ビュー           │
├─────────────────────────┤
│ ▁▂▃▅▂▁▃▅▇ ミニマップ      │
├─────────────────────────┤
│ ←  ↑  ↓  →  │8px│ 複製 削除 ↶│ ★常設・スクロールしない
├─────────────────────────┤
│ [床][橋][移動床][敵][結晶]… │ ★常設・横スクロールのパレット
├─────────────────────────┤
│   詳細設定（ここだけ縦スクロール） │
└─────────────────────────┘
```

- 常設バーのボタンは **52×48px** を維持
- 「試遊」は上部バーへ移す（`試す` タブは不要）
- 詳細設定へ落とすもの: 編集範囲・選択パーツのドロップダウン・数値欄・移動/成長の各項目・区間ジャンプ・修正メモ・書き出し/破棄・階段配置
- 区間ジャンプ・修正メモ・書き出し・破棄・階段配置は、詳細のさらに奥（`<details>` で畳む）でよい

### B. 置いた直後のものを操作対象にする（配置モードは維持したまま）

**ここが今回の中心。**

- パーツを置いたら、**そのパーツを選択状態にする**
- **同時に、配置モードは解除しない。**パレットの選択も光ったまま
- したがって置いた直後、十字キー・削除・複製がそのまま効く
- もう一度キャンバスをタップすれば、また同じprefabを置ける。**操作対象は新しく置いたほうへ移る**
- 「配置をやめる」を押すか、別のパーツをタップしたときだけ配置モードが切れる

これで **置く → ちょっとずらす → また置く** が1画面・タブ切替なしで回る。

### C. 置く位置を指の上へずらす

ドラッグ時は既に `+60/zoom` のオフセットが入っている（`stage-editor.js:864`）が、**配置タップには入っていない**。置いた瞬間、パーツが指の下に隠れて見えない。

- 配置タップにも同じオフセットを適用する
- 置いた直後、そのパーツを**0.6秒ほど強調表示**する（どこに出たか分かるように）

### D. パーツの選び方をドロップダウン以外にも用意する

90項目のネイティブselectはスマホでは探せない。**消さなくてよいが、主にしない。**

- **キャンバスのタップ**（44px以内で一番近いものを拾う判定は実装済み）
- **ミニマップのタップ**で近くへ飛ぶ
- 常設バーに **「直前に置いたもの」へ戻るボタン**
- ドロップダウンは詳細設定の中へ

---

## 3. 検収条件

**実機（390×844）で次が成立すること。**

- **床を置く → 十字キーで8pxずらす → もう1枚置く、がタブ切替もスクロールもなしでできる**
- 置いた瞬間、そのパーツが指で隠れていない
- 十字キー・削除・複製・undoが、いつでもスクロールせずに押せる
- パレットがいつでも見えている
- 削除を誤タップしても元に戻せる
- PC側の操作は1つも変わっていない
- `npm run validate` と `npm run build` が通る

## 4. 守ること

- **PCの挙動を変えない。**`(pointer: coarse)` の分岐だけ触る
- 常設バーとパレットは**絶対にスクロール領域へ入れない**
- 見た目の良し悪しを自動検査しない
