## コース延長（2026-08-12 実施）

所長の指示「ひとまず倍ぐらいに伸ばしたい」に対応。**既存部分（x0〜5600）は一切動かさず、末尾に6区間を継ぎ足した。**

- ワールド: `5600×1560` → `11216×1560`
- 4段降下（`descent-a`〜`descent-d`）は据え置き。**降下は増やさず、最下段 `floor-5` を `4850〜11216` まで延長した**
- 出口リフト `exit-lift-01` と肉球スイッチ `exit-switch-01` を `x5236` → `x10852` の新しい終端へ移設
- 結晶データ 12個 → 21個、共有アイテム 6個 → 15個、敵 4体 → 8体
- 追加区間: `reboot-corridor` / `spike-garden` / `crystal-relay` / `conveyor-yard` / `specimen-shelf` / `exit-hall`

### 延長部の高さ規格

最下段の床 `y=1274` の上に、**ジャンプ高166pxを下回る154px刻み**で3段の棚を積んだ。

| 段 | y | 用途 |
|---|---|---|

| L1 | 1120 | 床に接地する段差。踏み台 |

**`lab-bridge-v1` の絵は上面から150px下まである。**y=1120の棚は床に接した段差として読め、y=966以上は浮いた棚として読める。この境目を意識せずに置くと、床の上に板が寝ているだけの絵になる。

### 延長部で守った配分の原則

- **上ルートに置いた結晶（`crystal-11` / `14` / `15` / `17`）は地上から取れない高さにした。**代わりに下ルートには通しで結晶とコインを置き、どちらを通っても取り分がある
- **安全な上ルートには小さい取り分（コイン）、危険な下ルートには大きい取り分（フィッシュドリンク・結晶）**を置いた。`spike-garden` がその型
- **敵は上下どちらにも置いた。**ネジニャビ2体は棚の上、ニャビクリーン2体は床。片側だけ安全にしない
- **出口前（`exit-switch-01` の240px手前より右）には危険を置かない。**最後のハザード `spikes-04` は `x10243` で終わる

### 延長部で意図的にやらなかったこと

- **床に穴を開けていない。**`killY=1420` は最下段の床から146pxしか下にないので、落とし穴は「落ちたら即死」になる。1Fは安全を見せる階なので、危険は結晶と敵に限った
- **降下段を増やしていない。**降り方は階の語彙（`FLOOR_DESIGN.md` §1-2）なので、1F内で5段目より下へは降ろさない

## 結晶成長ルート（実装済み）

- x3436の小型スイッチ付き培養装置から、`crystal-growth-vertical-01`の結晶核と群晶が上へ連鎖する
- 縦結晶の先端と一緒に上昇する培養装置から、`crystal-growth-horizontal-01`の群晶が右へ順次伝播する
- 成長パラメータはエディターの「成長方向／結晶数／生成間隔／安定時間／崩壊時間／結晶間隔」で制約付き調整が可能
- 横結晶はx4000の降下線を越えず、既存の正規降下を塞がない
- 縦結晶は結晶核から4セグメントが順次析出し、成長中は見えている先端上面だけがプレイヤーを運ぶ
- 横結晶は6セグメントが順次析出し、見えている長さだけ当たり判定を持つ
- 両方とも安定時間後に減光・白濁・亀裂を経て先端から崩壊し、培養装置を再度押して作り直せる
- 結晶用スイッチは小型培養装置。肉球スイッチは出口エレベーター以外へ流用しない

## 真因 — 上ルートが下ルートを完全に支配している

**所長の実プレイによる訂正（2026-08-15）**: 上ルートは楽に登れる。むしろ**下ルートに行く動機がなく、下のほうが行きにくい**。

> 一度、床から床への単発ジャンプだけを机上計算して「上ルートは到達困難」と誤った結論を出した。実際の経路（移動床に運ばれる分、前区間から降りてくる高さ、敵を踏んだ反動）を勘定していなかったため。**静的な数字で経路を判断しない。**

実際の問題は到達性ではなく、**報酬の偏り**だった。これはデータから確認できる。

## 検査の穴

`tools/audit_course.mjs` は**報酬がどちらのルートに属するかを見ていない。**上ルートの `reward: true` が地上から取れないことは検査しているが、**「下ルートに報酬が残っているか」は見ていない。**

ルート選択の崩壊は**静かに壊れる**（画面もデータも正常に見える。プレイして初めて「下に行く意味がない」と分かる）ので、検査に値する。組み直しのときに次を追加する。

- **分岐がある区間では、両方のルートに報酬が存在すること**
- **危険が片方のルートに偏っていないこと**（危険だけあって報酬がないルートを作らない）
- 参考: 現状の後半は 上6個 / 下2個、敵は下に2体、上に0体

## 組み直しのときの原則（未確定・要所長承認）

- **ルート選択は「どちらにも取り分がある」ときだけ成立する。**片方に報酬を集めると、もう片方は通る理由がなくなる
- **安全なほうに報酬を集めない。**上が安全なら、上の取り分は小さくする。危険なほうに大きい取り分を置く
- **報酬は見えなくてよい。**むしろ全部見えていると選択が作業になる。詳細は `docs/FLOOR_DESIGN.md` §3-4
- **危険と操作だけは常に読めること。**読めない危険は迷いではなく理不尽
- **迷わせる分岐は1ステージに1〜2箇所。**誘導が基本、迷いはスパイス
- **ほぼ同じ高さの床を横に重ねない。**段差はジャンプ高166pxを基準に、意味のある差をつける
- 前半（チュートリアル区間）はいまの形を維持する

### 訂正の記録

当初ここに「上ルートは**見えて**、行けて、報酬があることが必要」と書いたが、**誤り**（2026-08-15 所長指摘）。読みやすさを報酬とルートに当てていた。当てる対象は危険と操作であって、報酬とルートの先は隠してよい。

## 教訓（記録）

**経路の良し悪しを静的な数字だけで判断しない。**床から床への単発ジャンプの計算は、実際の経路（移動床、前区間からの落差、敵の反動）を無視するので結論を誤る。判断が要るときは実際に走らせるか、所長のプレイ所感を正とする。
