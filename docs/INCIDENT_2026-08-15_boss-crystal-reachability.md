# ボスエリア結晶足場・到達不能インシデント報告

- 発生日: 2026-08-15
- 対象: COURSE 3 ボスエリアの結晶足場ルート
- 重要度: 高（必須進行ルートの到達不能）
- 状態: 修正・恒久対策実装・回帰検証中

## 事象

ボスエリアの高床を「通常ジャンプでは届かず、生成した結晶足場を経由すると届く」構成へ変更した際、最初の修正では下段結晶から高床へ届かず、次の修正では地上から下段結晶へ届かなくなった。

結晶足場が必須進行経路であるため、プレイヤーはボスの弱点へ到達できず、ゲーム進行不能になる問題だった。

## 直接原因

プレイヤーの理論上の最大上昇量は次式で約166pxとなる。

`jumpVelocity^2 / (2 * gravity) = 835^2 / (2 * 2100) ≒ 166px`

最初の配置では以下の不均衡があった。

- 地上 → 下段結晶: 154px（到達可能）
- 下段結晶 → 高床: 190px（到達不能）

次の修正では、接地判定用の `landingTolerance: 10px` をジャンプ上昇量へ加算し、176pxまで到達可能だと誤って判断した。

- 地上 → 下段結晶: 174px（実際には到達不能）
- 下段結晶 → 高床: 170px（実際には余裕不足）

`landingTolerance` は着地交差判定の許容値であり、ジャンプ頂点を高くする値ではない。到達可能高度へ加算したことが計算上の誤りだった。

## 構造上の原因

床、結晶足場、噴出口、スイッチのY座標を別々の固定値として編集していた。

そのため、高床を動かした際に以下を個別に追従させる必要があり、一部だけがずれる状態を作りやすかった。

- 下段・上段の結晶足場
- 高床と最上段床
- 高床上のスイッチ
- 高床上の噴出口
- 各ジャンプ区間の高低差

また、既存テストは「高床全体が通常ジャンプで届かない」ことだけを検査し、中間足場を含む各区間の到達可能性を検査していなかった。

## 修正内容

ボスエリアの縦配置を `data/course-layout.json` の `bossArenaLayout` に集約した。

管理対象:

- `groundY`: 地上床面
- `highTierRise`: 地上から高床までの総高度
- `topY`: 最上段床面
- `lowerStepRise`: 地上から下段結晶までの高度
- `upperStepRise`: 高床から上段結晶までの高度
- `switchHeight`: スイッチ本体高
- `nozzleHeight`: 噴出口高
- `jumpSafetyMargin`: 理論最大上昇量から差し引く安全余裕

`src/course-layout.js` の `applyBossArenaLayout()` が、この定義から左右両側の床・結晶・スイッチ・噴出口のY座標を一括算出する。今後は各オブジェクトのY座標を個別調整しない。

## 再発防止策

### 1. 単一の正本

ボスエリアの縦方向パラメータは `bossArenaLayout` だけを正本とする。左右のオブジェクトは同じ式から算出し、個別の座標を調整しない。

### 2. 接地許容値をジャンプ高度へ加算しない

到達判定には理論最大上昇量そのものを上限として使い、さらに `jumpSafetyMargin` を差し引く。

`allowedRise = theoreticalJumpRise - jumpSafetyMargin`

### 3. 経路を区間単位で検査

以下の4区間を左右それぞれ自動検査する。

1. 地上 → 下段結晶
2. 下段結晶 → 高床
3. 高床 → 上段結晶
4. 上段結晶 → 最上段

全区間が `allowedRise` 以下でなければビルド前検証を失敗させる。

### 4. 必須経路とショートカット条件を同時検査

- 地上から高床へ直接は届かないこと
- 結晶足場を使った全区間は届くこと

この両方を満たすことを完成条件とする。

### 5. 床付属物を床面から算出

スイッチと噴出口は所属床面から本体高を引いて配置する。床の高さを変更した場合も接地位置が自動追従する。

### 6. 実際のプレイヤー制御で自動シミュレーションする

静的な高低差計算に加え、製品コードと同じ `stepPlayerController()` を60fpsで動かし、各区間で実際に着地イベントが発生することを検査する。地上から高床への直接ジャンプは失敗することも同時に検査する。

### 7. 数値検査だけで完了扱いにしない

デバッグ開始位置から、結晶の起動、最下段への着地、高床への着地、最上段への到達までを実画面で通し確認する。必須ルートの変更では、静止画確認だけで完了扱いにしない。

## 完了条件

- 地上から高床へ直接到達できない
- 左右どちらも結晶足場経由で最上段まで到達できる
- スイッチと噴出口が所属床へ接地する
- ボスの移動・レーザー・召喚空間を塞がない
- `validate:boss` を含む全検証が通る
- 実操作による通し確認が完了する

## 2026-08-16 追補: 三段構成とボス高度同期

当初の実装が指示図より一段少なかったため、左右それぞれを三回の結晶展開に統一した。

1. 地上 → 下段結晶 → 1段目床
2. 1段目床 → 中段結晶 → 2段目床
3. 2段目床 → 上段結晶 → 3段目床

三つの床面と中間結晶の高さは、すべて `bossArenaLayout` の `firstFloorRise`、`tierRise`、`lowerStepRise`、`interTierStepRise` から算出する。

ボス高度も残りHPと同じ正本へ同期した。

- HP 3（ノーダメージ）: 1段目床から頭部へ攻撃可能
- HP 2（1ダメージ）: 2段目床から頭部へ攻撃可能
- HP 1（2ダメージ）: 3段目床から頭部へ攻撃可能

被弾後は次の段へ滑らかに上昇し、前の段からは頭部へ届かない。自動検査では、各6ジャンプ区間の実着地、一段飛ばし不能、各HPの指定床からの攻撃可能性、前段からの攻撃不能を確認する。

実画面確認時に、ボススプライト上部の透明余白によって頭部判定と見た目が約125pxずれていた問題も検出した。描画位置を透明余白分だけ補正し、レーザー原点も腕の砲口へ合わせた。
